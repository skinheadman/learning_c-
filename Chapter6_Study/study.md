### 6. 함수 중복과 static 멤버
##  6.1. 함수 중복
#   6.1.1. 중복 함수 조건
    - 조건
        - 이름 동일
        - 매개 변수 타입이나 매개 변수의 개수 달라야 함
        - 리턴 타입은 고려되지 않음
    - 실패 사례
        - 함수 이름, 매개 변수 타입이 같고 리턴타입만 다른 경우, 중복이 성립되지 않음.
#   6.1.2. 함수 중복의 편리함
    - 이름을 구분지어 구분할 필요가 없어 함수를 잘못호출하는 실수 줄임
    - 함수 중복은 컴파일시 이루어지기 때문에, 함수 중복으로 인한 실행시간 저하는 없음.
#   6.1.3. 생성자 함수 중복
    - 매개 변수를 통해 다양한 형태로 초깃값 전달 가능
#   6.1.4. 소멸자 함수 중복

##  6.2. 디폴트 매개 변수
#   6.2.1. 디폴트 매개 변수 선언
    - 미리 정해진 디폴트 값을 받도록 선언된 매개 변수 : 디폴트 매개 변수
    - 매개 변수 = 디폴트 값 의 형태
    - 디폴트 값을 전달하는 것은 컴파일러에 의해 처리
#   6.2.2. 디폴트 매개 변수에 관한 제약 조건
    - 끝 쪽에 몰려 선언되어야 함.
#   6.2.3. 매개 변수에 값을 정하는 규칙
    - 디폴트 매개 변수를 가지고 있는 함수의 호출문을 컴파일할 때, 컴파일러는 함수 호출문에 나열된 실인자 값들을 앞에서부터 순서대로 매개 변수에 전달, 나머지는 디폴트 값으로 전달
    - 디폴트 매개 변수만 가진 함수
        - 앞에서부터 차례대로 실인자 값 매개 변수에 전달
    - 디폴트 매개 변수와 보통 매개 변수를 가진 경우
        - 이것도 위와 동일 단, 보통 매개 변수에는 값을 넣어줘야 함.
        - 디폴트 매개 변수는 변수에 초깃값을 지정하는 것과 유사
        - 함수 호출문으로부터 디폴트 매개 변수에 전달되는 값을 정하는 것은 컴파일러의 기능
    - 포인터 변수의 디폴트 값
        - NULL, 문자열 등등 다 가능함.
#   6.2.4. 함수 중복 간소화
    - 디폴트 매개 변수를 사용하여 함수 중복 간소화 가능
    - 디폴트 매개 변수를 가진 함수는 같은 이름의 중복 함수들과 함께 선언될 수 없음.

##  6.3. 함수 중복의 모호성
#   + 종류 3가지
    - 형 변환으로 인한 모호성
    - 참조 매개 변수로 인한 모호성
    - 디폴트 매개 변수로 인한 모호성
#   6.3.1. 형 변환으로 인한 모호성
    - 함수의 매개 변수 타입과 호출문의 실인자 타입이 일치하지 않는 경우, 컴파일러는 보이지 않게 형 변환을 시도
    - 자동 형 변환
        char -> int -> long -> float -> double
        : 왼쪽에 있는 타입이 오른쪽에 있는 타입으로 형변환 가능
    - 매개 변수의 자료형만 다를 때, 컴파일러는 정수3을 float 타입으로 변환할지, double 타입으로 변환할지 모호하다고 판단. 컴파일 오류 발생
#   6.3.2. 참조 매개 변수로 인한 모호성
    - 참조 매개 변수를 가진 함수와 보통 매개 변수를 가진 함수가 중복될 때, 함수 호출의 모호성으로 인해 컴파일 오류가 발생하는 경우가 보임.
#   6.3.3. 디폴트 매개 변수로 인한 모호성
    - 디폴트 매개 변수를 가진 함수와 보통 매개 변수를 가진 함수가 중복될 경우, 함수 호출의 모호성으로 인해 컴파일 오류가 발생
    - 잘못된 함수 중복
        - 배열과 포인터의 이름이 같을 때, 배열의 이름은 포인터이기 때문에 같은 이름을 매개 변수로 가진 배열과 포인터가 담긴 함수는 같은 함수이다.

##  6.4. static 멤버
#   6.4.1. static의 특성
    - static : 변수와 함수의 생명 주기와 사용 범위를 지정하는 방식 중 하나
    - 생명 주기 : 프로그램이 시작할 때 생성되고 프로그램이 종료할 때 소멸
    - 사용 범위 : 변수나 함수가 선언된 범위 내에서 사용, 전역 혹은 지역으로 구분
    - non-static 멤버 : 각 객체마다 별도로 생성, 인스턴스 멤버
    - static 멤버 : 각 클래스 당 하나만 생기고 모든 객체들이 공유, 클래스 멤버
#   6.4.2. static 멤버 선언
    - 멤버 함수나 멤버 변수의 선언문 앞에 static 지정자를 붙이면 됨.
    - 모든 멤버들이 static으로 지정될 수 있으며, private, public, protected 등 어떤 접근 지정도 가능
    - static 변수의 공간 할당은 반드시 프로그램의 전역 공간에서 선언해야 함.
    - static 멤버와 non-static 멤버 비교
        1. 선언 사례 : static 자료형 멤버 함수(변수)명 / 자료형 멤버 함수(변수)명
        2. 공간 특성 : 클래스 당 멤버 하나 생성 / 객체마다 별도 생성
        3. 시간적 특성 : 프로그램과 생명을 같이 함 / 객체와 생명을 같이 함
        4. 공유의 특성 : 동일한 클래스의 모든 객체들에 의해 공유됨 / 공유되지 않음
#   6.4.3. static 멤버 사용 : 객체의 멤버로 접근하는 방법
    - 객체 이름이나 객체 포인터를 이용하여 보통 멤버와 동일하게 다루면 됨.
        - 객체.static멤버
        - 객체포인터 -> static 멤버
#   6.4.4. static 멤버 사용 : 클래스명과 범위지정 연산자(::)로 접근
    - 사용 방법
        - 클래스의 이름으로 접근 가능 (클래스 당 하나만 있으므로)
        - static 멤버 사이에 범위 지정 연산자(::)를 사용
            - 클래스명::static멤버 = 실인자값
            - 그냥 객체의 멤버로 접근하는 것과 동일하다.
#   6.4.5. static의 활용
    - 전역 변수나 전역 함수를 클래스에 캡슐화
    - 객체 사이에 공유 변수 제작
#   6.4.5. static 멤버 함수의 특징
    - static 멤버 함수는 오직 static 멤버들만 접근
        - static 멤버 함수는 오직 static 멤버 변수에 접근하거나 static 멤버 함수만 호출할 수 있음.
            -non-static 멤버 변수나 함수는 main함수가 생성될 때, 생성되므로 이를 static 함수가 호출하면 생기지도 않은 멤버 변수나 함수를 호출하는 것임
            - 그 반대는 사용 가능함.
    - static 멤버 함수는 this 사용 불가
        - this를 사용 불가하도록 지정 : 프로그램이 생성될 때 같이 생성되기 때문
