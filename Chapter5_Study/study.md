### 함수와 참조, 복사 생성자
##  5.1. 함수의 인자 전달 방식 리뷰
#   5.1.1. 인자전달방식
    - 값에 의한 호출 : 호출하는 코드에서 넘겨주는 실인자 값이 함수의 매개 변수에 복사되에 전달
    - 주소에 의한 호출 : 주소를 직접 포인터 타입의 매개변수에 전달받는 방식
    - 함수호출시 배열 전달 : 배열이 잔달되는 경우, 배열의 이름이 전달 = 주소에 의한 호출(배열의 주소는 곧 배열의 이름이기 때문)
#   5.1.2. 값에 의한 호출과 주소에 의한 호출의 특징
    - 값에 의한 호출 
        - 실인자의 값을 복사하여 전달하므로, 함수 내에서 실인자를 손상시킬 수 없다는 장점
        - 함수 호출에 따른 부작용이 없다.
    - 주소에 의한 호출
        - 실인자의 주소를 넘겨주어 의도적으로 함수 내에서 실인자의 값을 변경하고자 할 때 이용
##  5.2. 함수 호출시 객체 전달
#   5.2.1. 값에 의한 호출로 객체 전달
    - 값에 의한 호출 과정
        - 메인함수에 객체 생성 -> 함수 호출 -> 객체 복사 -> 새로운 매개 변수 객체 생성 -> 새로운 매개 변수 객체의 값 변화 -> 함수 종료와 함께 매개 변수 객체 소멸 -> 메인함수 객체값 표시
        - 메인함수에 있는 객체 자체의 값은 변하지 않음
    - 값에 의한 호출 시 객체 복사 시간
        - 매개 변수 객체에 어떤 변화가 일어나도 실인자 손상 x
        - 실인자 객체의 크기가 크면 객체를 복사하는 시간이 커짐
    - 문제점
        - 객체가 함수에 전달되면, 함수의 매개 변수 객체가 생성되고, 함수가 종료하면 매개 변수 객체가 소멸됨.
            -> 이때, 매개 변수 객체의 생성자와 소멸자가 모두 실행되느냐?
            -> 아님, 객체를 매개 변수로 가지는 함수의 경우, C++ 컴파일러에서 매개 변수 객체의 생성자는 실행되지 않고 소멸자만 실행되도록 컴파일
            -> 생성자의 실행 없이 객체의 값 그대로 매개 변수 객체에 복사됨
    - 문제의 이유 (매개 변수 객체의 생성자가 생성되도록 컴파일 하지 않는 이유)
        - 생성자가 실행되면, 전달 받은 원본의 상태를 잃어버리기 때문
        - 소멸자는 그냥 소멸시키는 기능을 하기 때문에 그냥 실행
    - 해결책 : 복사 생성자
        - '값에 의한 호출' 시, 컴파일러는 매개 변수 객체의 생성자 대신 복사 생성자가 호출되도록 컴파일하기 때문에, 생성자가 실행되지 않는 것.
        - 클래스에 복사생성자를 호출하지 않는 경우, 컴파일러는 실인자 객체의 멤버 편수를 매개 변수 객체에 그대로 복사하는 디폴트 복사 생성자를 자동으로 삽입
#   5.2.2. 주소에 의한 호출로 객체 전달
    - 주소에 의한 호출 과정
        - 주소를 전달받아야 하므로 함수를 선언할 때, 매개 변수로 포인터 변수를 설정하고, 메인 함수 객체를 복사할 때, 그 주소값을 주면 됨.
        - 그러면 포인터 변수는 객체가 아니므로 생성자와 소멸자에 영향을 받지 않아 값을 변화시킬 수 있음.
        - 메인 함수 객체 생성 -> 함수 호출 함수(객체 주소값) -> 주소가 포인터 변수에 전달 -> 포인터 변수에 담긴 주소값 내부의 내용 변환 -> 함수 종료시 포인터 변수 소멸 -> 화면에 출력됨.
    - 주소에 의한 호출 특징
        - '값에 의한 호출'에 비해 원본 객체를 복사하는 시간 소모 없음.
        - 생성자 소멸자의 비대칭 문제 없음.
        - 원본 객체 훼손 가능성 있음
##  5.3. 객체 치환 및 객체 리턴
#   5.3.1. 객체 치환
    - 객체 치환 시 객체의 모든 데이터가 비트 단위로 복사
    - 내용물은 같은데 두 객체는 별개임
    - 동일한 클래스 타입에만 적용
#   5.3.2. 함수의 객체 리턴
    - return 실행과 함께 리턴값의 복사본 생성, 이 복사본이 전달됨. 이후, 리턴값 소멸
    - 객체를 받는 코드 : 객체 = 함수();
##  5.4. 참조와 함수
#   5.4.1. 참조 개념
    - 참조 변수 : & / 포인터 변수 : *
    - 즉 참조는 별명을 붙이는 것
    - 참조의 활용 : 참조 변수, 참조에 의한 호출, 함수의 참조 리턴
#   5.4.2. 참조 변수
    - 참조 변수 선언
        - 참조변수 : 이미 선언된 변수(원본 변수로 지칭)에 대한 별명
        - 참조자(&)를 이용하여 선언
        - 반드시 원본 변수로 초기화 필요
            ex. 자료형 &참조변수명(객체명) = 원본 변수(객체)
        - 참조변수는 이름만 생성되고, 공간이 할당되지 않음.
        - 대신, 초기화로 지정된 원본 변수의 공간 공유
    - 참조 변수 사용
        - 보통 변수와 동일한 방법
        - 원본 변수의 사용 -> 원본 변수의 공간을 공유하기 때문
        - 포인터가 아님. 그냥 . 찍으셈
        - 참조 변수에 대한 포인터 생성 가능
    - 참조 변수 선언시 주의 사항
        - 초기화가 없다면 컴파일 오류 발생 -> 어떤 변수에 대한 참조 변수인지 초기화 되지 않음.
        - 참조자의 위치에 무관
        - 참조자의 사용에 유의 무조건 자료형 & 참조 변수명(객체명) = 원본 변수(객체)
        - 배열을 만들 수 없음 (이건 포인터랑 다르네)
        - 참조 변수에 대한 참조 선언이 가능 -> 모두 원본 변수의 공간 공유 그냥 말그대로 별명임
#   5.4.3. 참조에 의한 호출, call by reference
    - 참조에 의한 호출
        - 함수의 매개 변수를 참조 타입으로 선언
        - 매개 변수가 함수를 호출하는 쪽의 실인자를 참조하여, 실인자와 공간을 공유
        - 이런 식의 매개 변수 = 참조 매개 변수
            ex. 자료형 함수명(&매개 변수명)
        - 함수의 원형에 의해 구분 -> 함수의 원형에 참조 매개 변수를 작성해야함.
        - 작동 과정
            함수의 원형에 참조 매개 변수 선언 -> 참조 매개 변수를 보통 변수처럼 사용 -> 이름만 생성되고 변수 공간 공유 -> 함수의 스택에서 바뀐 내용이 메인의 스택에서도 적용됨
    = 참조 매개 변수가 필요한 사례
        - 리턴값이 명확하지 않을 때 -> 잘못해서 0을 호출했는데 평균이 0으로 인식될 수 있음.
        - 그럴 때, bool형 함수로 바꾸고 평균값으로 참조 매개 변수를 선언하고 그 값을 함수 내부에서 변경한 다음, 참조 매개 변수를 출력하면 됨.
    - 참조에 의한 호출의 장점
        - 주소에 의한 호출에서의 불편함 (코딩시 실수, 코드의 가독성 떨어짐) 해결
        - 간단히 변수만 넘겨주면 됨.
    - 참조에 의한 호출로 객체 전달
        - 참조 매개 변수로 이루어진 모든 연산은 원본 객체에 대한 연산이 됨.
        - 참조 매개 변수는 이름만 생성되므로, 생성자와 소멸자는 실행되지 않음.
#   5.4.4. 참조 리턴
    - 변수 등과 같이 현존하는 공간에 대한 참조의 리턴
    - 자료형 & 함수명() 내용
        -> 그 자료형으로 이루어진 모든 것에 대하여 참조할 수 있는 함수를 만드는 거?
        -> 지정한 변수에 대한 참조를 리턴
    - 참조 리턴에 대한 치환문
        - 참조의 리턴을 하는 함수를 다시 참조하여 지정한 변수의 값을 바꿀 수 있음.
    - string 클래스 멤버 함수들이나 C++ 라이브러리에는 참조를 리턴하는 함수들이 많음. 그렇기에 중요
#   참조와 포인터 자료형
    - 자료형 변수명 = 값 -> 변수명을 값으로 초기화
    - 자료형 *변수명 = &변수 -> 포인터 변수 생성, 포인터 변수는 & 연산자로 지정한 변수의 주소값을 가짐
    - 자료형 &변수명 = 변수 -> 참조 변수 생성, 참조 변수는 변수와 공간을 공유함. 즉 별명임.
    - L-value : 공간, R-value : 값, '=' : 치환 연산자
    - 무언가를 리턴하는 함수는 L-value에 위치할 수 없음. 단, 참조 변수 등 변수를 리턴하는 건 제외
##  5.5. 복사 생성자
#   5.5.1. 얕은 복사와 깊은 복사
    - 객체의 얕은 복사와 깊은 복사
        - 얕은 복사 진행 : 메모리 공유 문제 발생
        - 깊은 복사 진행 : 별개의 메모리 할당 -> 문제 발생 x
    - 객체의 얕은 복사의 문제점
        - 메모리를 공유하고 있기 때문에 둘 중 하나가 변경되면 둘 다 변경됨
#   5.5.2. 복사 생성 및 복사 생성자
    - 복사 생성자 선언
        - 복사 생성자 : class명(const class명& 변수명)
        - 매개 변수는 오직 하나, 자기 클래스에 대한 참조로 선언됨.
        - 복사 생성자는 클래스에 오직 하나만 생성할 수 있음.
    - 복사 생성자 실행
        - 메인 함수의 객체가 함수에 있는 참조 매개 변수로 전달되어 복사생성자 실행
        - 메인 함수 객체 선언 -> 메인 함수 복사 객체 선언(메모리값 할당) -> 복사 생성자 실행으로 복사 객체에 메인 함수 객체의 값을 복사
    - 디폴트 복사 생성자
        - 얕은 복사를 실행하도록 만든 코드
#   5.5.3. 얕은 복사 생성자의 문제점
    - 원본 객체가 할당받은 메모리를 사본 객체가 공유
    - 디폴트 복사 생성자 자동 삽입
    - 실행
        원본 객체 생성 -> 복사 객체 생성 -> 동일한 메모리 공유에 의한 동일한 값 도출 -> 하나에서 변경시 다 변경 -> 객체 소멸시, 메모리 반환되므로, 둘 중 하나라도 소멸하면 비정상 접근 오류 발생
#   5.5.4. 사용자 복사 생성자 작성
    - 실행
        원본 객체 생성 -> 복사 객체 생성 -> 복사 생성자에 의한 다른 메모리값 할당 -> 변경시 그 객체의 메모리에 담긴 값만 변경 -> 각 객체마다 메모리 할당되었으므로, 자연스럽게 소멸시 메모리 반환
#   5.5.5. 묵시적 복사 생성
    - 종류
        1. 객체로 초기화하여 객체가 생성될 때
            - 새로운 객체를 생성하고 이를 객체로 초기화/ 치환문은 호출되지 않음.
        2. '값에 의한 호출'로 객체가 전달될 때
            - 생성자대신 복사 생성자 호출됨.
        3. 함수가 객체를 리턴할 때
            - 함수가 객체를 리턴할 때, return 문은 리턴 객체의 복사본을 생성하여 호출한 곳으로 전달
            - 이때, 복사본을 만들어 넘겨주고, 복사본이 만들어질 때 복사 생성자 호출
    - 이건 깊은 복사가 아님.
