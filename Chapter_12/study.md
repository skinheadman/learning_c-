#   12. C++ 파일 입출력
##  12.1. 텍스트 파일과 바이너리 파일
    - file : 저장 매체에 저장되는 정보, 바이트나 블록 단위로 입출력되고, 기록되는 데이터의 종류에 따라 나뉨.
    - text file : 오직 문자들만 저장 / binary file : 문자 외에 이미지 등 다양한 정보가 기록된 파일
### 12.1.1. 텍스트 파일
    - 텍스트 파일 : 글자 혹은 문자만으로 구성되는 문서 파일
    - 사람들이 사용하는 글자 : 한글, 영어 알파벳, 숫자, 기호, 특수문자 포함
        - 각 글자마다 고유한 바이너리 코드(이진 코드) 주어짐
        - 영어 문자에 대한 코드 체계 : ASCII 코드
        - 전 세계 언어에 대한 코드 체계 : Unicode
        - ASCII 코드로 되어있는 텍스트 파일에는 문자 코드만 저장됨.
        ex. txt file, HTML file, XML file, C++ 소스 파일, C 소스 파일, 자바 소스 파일 등
    1. 텍스트 파일 내부 보기
        - 텍스트 파일에는 문자로 해석 가능한 코드 값들만 존재
        - 파일의 첫 바이트 0x57 - 문자 'W' 값에 해당하는 ASCII 코드
        - 'river' : 0x72, 0x69, 0x76, 0x65, 0x72 값으로 저장
        - <Space> : 빈칸, ASCII 코드 값 0x20으로 저장
        - <Enter> : '\r':0x0D, '\n':0x0A 두 제어문자로 기록
        - 파일의 마지막 부분의 1961 -> '1'은 문자로서 0x31로 저장
        - 텍스트 파일에는 문자 코드가 아닌 어떤 값도 존재할 수 없음.
        - 0xFF, 0x01, 0x02 바이트에 해당하는 ASCII 문자는 없음. -> 있으면 바이너리
    2. 텍스트 파일과 Enter 키
        - 텍스트 편집기 : <Enter> 키를 '\r'과 '\n'의 두 ASCII 코드로 저장
        - 코드값 : 0x0D(십진수 13), 0x0A(10진수 10)
        - '\r' : carriage return 제어 코드, 커서를 현재 줄의 맨 앞으로 옮기도록 하는 지시
        - '\n' : line feed 제어 코드, 커서를 현재 있는 위치에서 한 줄 밑으로 옮기도록 하는 지시
        - 다음줄로 넘어가려면 carriage return 과 line feed가 모두 필요함.
### 12.1.2. 바이너리 파일
        - 사진 이미지, 오디오, 그래픽 이미지, 컴파일된 코드 : 문자로 표현되지 않는 바이너리 정보
        - 바이너리 파일은 위의 정보를 저장함.
        - 텍스트 파일의 각 바이트들은 모두 문자들로 해석 but, 바이너리 파일의 각 바이트는 파일을 만든 응용프로그램만이 해석 가능
            - 바이너리 파일 종류
                - jpeg, bmp 등의 이미지 파일
                - mp3 등의 오디오 파일
                - hwp, doc, ppt 등의 확장자를 가진 멀티미디어 문서 파일
                - obj, exe 등의 확장자를 가진 컴파일된 코드나 실행 파일
        1. 바이너리 파일 내부 보기
            - 파일 내의 주소와 파일 내부의 바이너리 데이터(16진수 표현) 존재
            - 문자로 해석할 수 없는 바이너리 값들이 존재
            - ASCII 문자나 유니코드 문자 존재 x
### 12.1.3. hwp 파일은 텍스트 파일인가 바이너리 파일인가
    - 바이너리 파일임.
    - 문서나 글자에 지정된 포맷 정보는 문자가 아닌 바이너리 정보로 파일에 저장됨.
    - 결국 바이너리 파일임.

##  12.2. 파일 입출력 개요
### 12.2.1. C++ 파일 입출력 라이브러리
    - ifstream : 파일 읽기 시에 사용
    - ofstream : 파일 쓰기 시에 사용
    - fstream : 하나의 파일에 읽기와 쓰기를 동시에 할 때 사용
    -> template 클래스에 char 타입으로 구체화 하고 typedef로 선언됨
### 12.2.2. 파일 입출력 스트림은 파일을 프로그램과 연결한다.
    - ifstream, ofstream : 파일을 프로그램과 연결하는 스트림
    - 프로그램 : ifstream - reading, ofstream - writing
    - istream - get() : 스트림이 키보드에 연결되어 있다면 키보드에서 문자 하나를 읽음. / 스트림이 파일에 연결되어 있다면 파일에서 문자 하나를 읽음.
    - ifstream 스트림 객체와 ofstream 스트림 객체가 파일을 연결-> get(), getline(), put(), read(), write() 등의 멤버 함수 스트림에 연결된 파일에서 읽고 쓰기 진행
### 12.2.3. 헤더 파일과 namespace
    - ifstream, ofstream, fstream 이용 -> fstream 헤더 파일과 std 이름공간이 필요
### 12.2.4. 파일 입출력 모드 : 텍스트 I/O와 바이너리 I/O
    - 텍스트 I/O : 문자들만을 기록하고, 파일에 있는 바이트를 문자로만 해석하는 입출력 방식 
        -> 텍스트 파일을 읽고 쓸 때만 사용
    - 바이너리 I/O : 바이트 단위로 데이터를 입출력하는 방식
        -> 모든 파일을 단순히 바이트의 스트림 단위로 다룸 : 텍스트 파일이나 바이너리 파일에 상관없이 읽고 쓰기 가능
    - 파일 입출력 모드는 if, of, fstream의 생성자에 지정하거나 파일 열기시에 지정해야 함.

##  12.3. <<와 >> 연산자를 이용한 간단한 텍스트 파일 입출력
    - <<와 >> 연산자는 오직 텍스트 파일에 대해서만 작동
### 12.3.1. 파일 쓰기를 위한 스트림 객체 생성
    - ofstream fout ; -> 파일 출력 스트림 객체 fout 생성
        -> 파일 쓰기는 fout을 이용하여 이루어짐.
### 12.3.2. 파일 열기
    - 파일명을 매개 변수로 설정
    - fout 객체의 open() 멤버 함수 호출 -> 파일을 열어 스트림에 연결
    - 코드 : fout.open("song.txt"); -> song.txt를 열고 스트림에 연결
    - 출력 스트림에 파일을 연결하는 과정
        -> if, read-only 파일이거나, 디스크 용량이 모자라는 등 파일 만들기가 불가능한 경우 파일 열기 실패
        -> open() : song.txt 파일이 존재하지 않으면 빈 song.txt 파일을 새로 만듦
        ->  이미 존재한다면 기존의 song.txt 파일의 내용을 모두 지우고 파일의 맨 앞에서부터 쓸 준비
        - fstream fout("song.txt") 이렇게 객체를 만들어 파일 출력 스트림 생성과 동시에 파일 열기를 같이 할 수 있음.
### 12.3.3. 파일 열기 성공 검사
    - 열기 실패 == 파일 쓰기 불가
        -> 열기 후에는 반드시 열기의 성공 여부 검사 필수
        - 코드 : if(!fout) {...}
    - !fout : fout 스트림의 operator!() 연산자 함수 실행
        - ios 클래스의 멤버 : 상속받은 모든 입출력 클래스에서 사용 가능
        - 열기가 실패한 경우 : true / 성공한 경우 : false return
        - is_open() 함수로도 확인 가능 -> 성공 : true / 실패 : false return
        - 코드 : if(!fout.is_open()) {...} -> !은 중복 연산자가 아님.
### 12.3.4. << 연산자를 이용한 파일 쓰기
    - 코드
    int age = 21;
    char singer[] = "Kim";
    char song[] = "Yesterday";

    ofstream fout("song.txt");
    if(!fout) return; // 열기 오류
    fout << age << '\n'; // 파일에 21과 '\n' 기록 -> << 연산자는 문자만 기록하기 때문에 21을 '2'와 '1'로 이루어진 문자열로 저장
    fout << singer << endl; // 파일에 "Kim"과 '\n' 덧붙여 기록
    fout << song << endl; // 파일에 "Yesterday"와 '\n' 덧붙여 기록
### 12.3.5. 파일 닫기
    - fout.close();
        -> close 함수를 호출하여 파일 닫기 -> 스트림은 파일과의 연결을 끊는다.
    - close 이후에는 파일 쓰기 불가능

##  참고 : 파일 열기, 닫기의 필요성
    - 파일 열기 : 경로명에 파일이 존재하는지, 파일 작성에 필요한 디스크 공간이 있는지, 읽기 전용 파일에 쓰기를 하는지, 접근 금지된 파일을 읽고자 하는지, 디스크는 정상적으로 작동하는지 등 검사하는 과정
        -> 모든 검사가 성공하였을 때, 파일 열림. => 스트림과 연결됨.
        -> 운영체제에 의해 이루어짐. 
        -> 열린 파일의 효율적인 입출력을 위한 구조 형성됨.
    - 파일 닫기 : 파일 열기 시에 구성한 자료 구조를 해제하여 읽기/쓰기를 끝내는 과정
        -> 버퍼에 남아 있는 데이터를 물리적으로 장치에 기록하는 마무리 작업 포함.
        -> 파일 닫기를 하지 않고 프로그램이 비정상적으로 종료되는 경우 : 버퍼에 남아있는 데이터가 파일에 기록되지 않을 수도 있음.
        -> 파일이 닫히면 쓰기 불가능, 다시 열고 써야함.
        -> 프로그램이 정상적으로 종료되면 열려진 파일은 모두 자동으로 닫힘.

### 12.3.6. >> 연산자를 이용한 텍스트 파일 읽기
    1. ifstream 클래스를 이용하여 파일 입력 스트림 객체 생성
        - 코드 : ifstream fin;
    2. open() 함수를 이용하여 파일 열고, 열기 성공 여부 확인
        - 코드
        fin.open("~");
        if(!fin) {...}
    3. 파일 열기가 성공하였으면 >> 연산자를 이용하여 파일에서 텍스트 데이터 읽기
        - 코드
        char name[10], dept[20];
        int sid;
        fin >> name; // 파일에 있는 문자열을 읽어 name 배열에 저장
        fin >> sid; // 숫자로 구성된 문자열을 정수로 변환
        fin >> dept; // 문자열을 읽어 dept 배열에 저장
    4. 파일 읽기 마치기
        -fin.close();

##  참고 : 파일의 경로명
    - 문자열에 \ 문자를 사용하고 싶으면 \\ 이렇게 두 번 쳐줘야 함.

##  12.4. 파일 모드
### 12.4.1. 파일 모드란?
    - 파일을 열 때, 앞으로 어떤 파일 입출력을 수행할 것인지 알리는 정보
    - ios 클래스에 상수로 선언
    - 파일에서 읽을 것인지, 쓸 것인지, 파일의 맨 뒤에서부터 쓸 것인지, 기존의 파일 내용을 지우고 처음부터 쓰기 시작할 것인지, 텍스트 I/O로 할 것인지, 바이너리 I/O로 할 것인지 등을 지정
    - 파일모드 상수
        - ios::in : 읽기 위해 파일 열기
        - ios::out : 쓰기 위해 파일 열기
        - ios::ate : (at end) 쓰기 위해 파일 열기, 열기 후 파일 포인터는 파일 끝, 파일 포인터를 옮겨 팡리 내의 임의의 위치에 쓸 수 있음.
        - ios::app : 파일 쓰기 시에만 적용, 파일 쓰기 시마다, 자동으로 파일 포인터가 파일 끝으로 옮겨져서 항상 파일의 끝에 쓰기 이루어짐.
        - ios::trunc : 파일을 열 때, 파일이 존재하면 파일의 내용을 모두 지워 파일 크기가 0인 상태로 만듦, ios::out 모드를 지정하면 디폴트로 함께 지정됨.
        - ios::binary : 바이너리 I/O로 파일 열기, 지정되지 않으면 디폴트는 텍스트 I/O
### 12.4.2. 파일 모드 설정
    - 파일을 열 때 지정
    - open() 함수나 ifstream, ofstream, fstream의 생성자를 통해 지정
    - open() 함수의 경우, 두 번째 매개 변수에 파일 모드 지정
    - 여러개의 파일 모드를 동시에 지정하고 싶으면 |(bit-OR) 연산자 이용
    - ifstream의 디폴트 파일 모드 : ios::in / ofstream의 디폴트 파일 모드 : ios::out / fstream의 디폴트 파일 모드 : ios::in | ios::out
    - 텍스트 I/O가 디폴트임.
    - 파일 모드를 지정하는 사례 -
    1. 처음부터 읽고자 하는 경우
        - 디폴트 파일 모드를 그대로 사용
        - 명시적으로 지정도 가능
    2. 파일의 끝에 데이터를 저장하는 경우
        - 코드
        ofstream fout;
        fout.open("student.txt", ios::out|ios::app);
        fout << "tel:010~~"; // 기존의 student.txt 파일 끝에 문자열을 추가 저장
    3. 바이너리 I/O로 data.bin 파일을 기록하는 경우
        - 코드
        fstream fbinout;
        fbinout.open("data.bin", ios::out|ios::binary);
        char buf[128];
        ...
        fbinout.write(buf, 128); // buf에 있는 128바이트를 파일에 기록
    4. 스트림 객체의 생성자를 이용한 파일 모드 지정
        ifstream fin("student.txt"); // 디폴트 파일 모드 ios::in 지정
        ofstream fout("student.txt", ios::out|ios::app);
        fstream fbinout("data.bin", ios::out|ios::binary);

##  12.5. 멤버 함수를 이용한 텍스트 I/O
    - 텍스트 파일을 읽기 위해서는 파일 모드를 텍스트 I/O로 지정 필요
    - get(), put() => istream과 ostream 클래스의 멤버로서, 텍스트 파일이나 바이너리 파일을 막론하고 입출력 가능
### 12.5.1. 텍스트 I/O 모드로 열기
    - ios::binary를 지정하지 않으면, 텍스트 I/O로 입출력이 이루어짐. 
    - 코드
    const char* file = "c:\\users\\~.ini"; // 텍스트 파일
    ifstream fin; // 파일 입력 스트림 객체 생성
    fin.open(file); // 텍스트 I/O로 파일 열기
    ...
    ofstream fout(file); // 파일 출력 스트림을 생성하고, 텍스트 I/O로 파일 열기
### 12.5.2. get() 과 put() 을 이용한 텍스트 I/O
    - 텍스트 I/O 모드인 경우, get() 은 파일에서 문자 한 개를 읽고, put() 은 문자 한 개를 파일에 기록
    - get()을 이용하여 파일에서 문자 읽어오기
### 12.5.3. get() 과 EOF
    - get() 이 EOF를 인식하는 방법
    1. get() 함수와 EOF의 관계
        - get()은 한 바이트를 읽고 파일 포인터를 다음 바이트 위치로 전진
        - get()이 파일의 마지막 문자를 읽고 나면, 파일 포인터는 전진하여 파일의 끝을 가리킴. -> 이때 eof() 함수를 입력하면 false(아직 파일의 끝에 도달하였는지 알 수 없음.)
        - 한 번 더 get() 을 실행하면 읽을 수 없는 파일 끝임을 확인하고 EOF(-1) 리턴
        - 스트림 내부에 eofbit 플래그를 1(true)로 설정
    2. get() 으로 파일의 끝을 인지하는 방법
        - get()이 리턴한 값과 EOF를 비교
        while(true) {
            int c = fin.get(); // 파일에서 문자(바이트) 읽기
            if(c==EOF) {
                ...
                break;
            }
            else {
                ... // 읽은 문자(바이트) c를 처리
            }
        }
        => 변형
        while((c = fin.get())!=EOF) {
            ...
        }
        - 텍스트 I/O나 바이너리 I/O에 상관없이 파일을 읽는 경우에 사용
    3. 파일의 끝을 잘못 인지하는 코드
        - eof()는 오직 eofbit 플래그의 값이 1인지만 확인하여 리턴
        - 문제가 발생하는 경우
        while(!fin.eof()) {
            int c = fin.get(); // 문제 위치, 마지막 읽은 EOF(-1) 값이 c에 리턴됨.
            ...  // 읽은 값 c를 처리하는 코드
        }
        -> while문의 eof() 가 실행되면 false 리턴함. -> 이유 : eofbit이 1로 설정되지 않았기 때문
        -> 이때 다시 fin.get() 이 실행되면 eofbit이 1로 셋, get()은 EOF(-1)을 리턴하여 c에 -1이 들어가게 됨.
        -> -1을 정상적으로 읽은 문자로 착각하고 처리함.
        => fin.get() 함수를 사용할 때에는 호출한 이후에 바로 fin.eof()를 호출하여 파일 데이터를 읽었는지 확인해야함.

##  참고
    - get()의 리턴 타입이 int 인 이유
    의문1. get() 함수는 한 바이트나 문자 하나를 리턴하는데 왜 리턴 타입이 char가 아닌 int 인가
    의문2. get()이 파일의 끝을 만나면 -1(EOF)를 리턴하는데, 파일에 -1이 있으면 둘을 어떻게 구분하는가
    -> 파일의 끝 처리와 연관
    -> 만일 스트림이나 파일의 끝에 0xFF 값이 있으면 get() 은 0xFF를 리턴
    -> get() 은 int를 리턴하기 때문에 0x00000FF로 리턴 => -1이 아닌 255 리턴
    -> EOF는 -1인 0xFFFFFFFF
    -> 구분 가능하기 때문에 get()의 리턴 타입이 int 임.

### 12.5.4. ios::app 모드로 텍스트 파일 덧붙여 쓰기
    - ios::app 모드를 이용하면 파일의 끝에 다른 파일을 덧붙여 쓸 수 있음.
    - get() 을 이용하여 두 번째 파일의 데이터를 읽고, put() 을 이용하여 첫 번째 파일에 덧붙여 기록
### 12.5.5. 텍스트 파일의 라인 단위 읽기
    1. istream의 getline(char* line, int n)
        -> istream의 getline() 함수는 스트림에 연결된 입력 장치나 팡리로부터 한 줄을 읽는 함수
            => EOF까지 파일을 라인 단위로 읽는 전형적인 코드
            => 한 라인을 읽고 fin&을 리턴하므로 결국 while(fin) 실행
            => 이 문장에서 C++11 표준부터 istream 클래스에 만들어져 있는 operator bool() 연산자 실행
            => 현재 스트림(fin) 내에 오류 상태(failbit 이나 badbit)를 검사하고 오류가 발생한 상태이면 false 리턴
            => 즉, getline()이 읽을 데이터가 없는 경우, while 문 끝남.
    2. ifstream& getline(ifstream& fin, string& line)
        -> <string> 헤더 파일에 선언된 함수 -> 파일에서 한 라인을 읽어 string 객체에 저장
        -> 한 라인이 몇 개의 문자로 구성되어있는지 상관 x -> string 사용

##  12.6. 바이너리 I/O
    - 바이너리 I/O는 파일의 각 바이트를 바이너리 값 그대로 읽거나, 변수나 버퍼의 바이너리 값을 그대로 파일에 저장하는 저수준 입출력 방식
### 12.6.1. 바이너리 I/O로 파일 열기
    - ios::binary 파일 모드 지정
### 12.6.2. get()과 put()을 이용한 바이너리 I/O
    - get() 과 put()은 텍스트 파일로부터 문자를 읽거나 문자를 기록하는데도 사용되지만, 바이너리 바이트를 읽고 쓰는데도 사용됨.
    - 다른 것과 동일, c = fsrc.get() 이런 거 처럼 그냥 읽고, fdest.put(c) 처럼 그냥 출력함.
### 12.6.3. read()/write()로 블록 단위 파일 입출력
    - get() 과 put()은 한 바이트 단위로 입출력 수행, read()와 write()는 블록 단위로 입출력
    - read() 함수 : istream의 멤버 ifstream이 상속받음.
        -> istream& read(char* s, int n);
        -> 읽는 도중 파일 끝에 도달하면 읽기 중단.
        -> 파일에서 최대 n개의 바이트를 배열 s에 읽어오기
        -> 정확하지 않기 때문에 gcount()로 실제 읽은 바이트 수 리턴 받아야 함. => 파일의 바이트 수를 정확하게 카운트 하려면 바이너리 I/O로 읽어야 함.
        -> 실행 속도가 get() 보다 빠름 => 블록 단위로 읽어오기 때문
    - write() 함수 : ostream의 멤버, ofstream이 상속 받음.
### 12.6.4. 바이너리 I/O와 텍스트 I/O의 차이점
    1. 파일의 끝을 인식하는 방법에는 차이가 없음.
        -> 파일의 끝은 모드에 상관없이 EOF와 비교하면 됨.
    2. 텍스트 I/O와 바이너리 I/O는 '\n'를 읽고 쓸 때, 서로 다르게 작동
        (1) 텍스트 I/O에서 '\n' 입출력
            - 기록 : \r, \n
            - 리턴 : \n
            - get()과 write() 둘다 동일하게 작동
        (2) 바이너리 I/O에서 '\n' 입출력
            - 기록 : \n
            - 리턴 : \n
            - get()과 write() 둘다 동일하게 작동
    - 즉, 전용함수가 따로 있는 것이 아닌, 파일 모드 설정에 따라 함수가 '\n'에 대하여 다르게 작동함.
    - >>, << 연산자는 텍스트 I/O에서만 작동함.

##  12.7. 스트림 상태 검사
    - 파일 입출력 스트림 : 스트림의 상태를 저장하는 멤버 변수를 두고, 입출력이 진행되는 동안 발생한 오류 정보 유지
    - 스트림의 상태를 나타내는 각 비트
        -> 앞에서부터 badbit, failbit, eofbit
        (1) eofbit : 파일의 끝을 만났을 때 1
        (2) failbit : 정수를 입력받고자 하였으나 문자열이 입력되는 등의 포맷 오류나, 쓰기 금지된 곳에 쓰기를 시행하는 등의 전반적인 I/O 실패시에 1로 세팅
        (3) badbit : 스트림이나 데이터가 손상되는 수준의 진단되지 않는 문제가 발생한 경우나 유효하지 않는 입출력 명령이 주어졌을 때 1로 세팅
    - 스트림의 상태를 검사하는 멤버 함수
        (1) eof : 파일의 끝을 만났을 때 (eofbit=1) true 리턴
        (2) fail : failbit나 badbit가 1로 세팅되었을 때 true 리턴
        (3) bad : badbit이 1로 세팅되었을 때 true 리턴
        (4) good : 스트림이 정상적 (모든 비트가 0)일 때 true 리턴
        (5) clear : 스트림 상태 변수를 0으로 지움.

##  참고 : 파일의 마지막에 파일의 끝을 나타내는 EOF(-1) 데이터
    - 파일의 끝 : 파일의 마지막 데이터가 기록된 지점을 지난 물리적인 끝지점
    - 과거 : EOF 문자 자동 기록 (0x1A) - 텍스트 파일 / 바이너리 파일은 아무것도 없음.
    - 현재 : 둘 다 없음.
    - 파일의 끝을 인식하는 작업은 운영체제(OS)의 몫
    - 입출력 라이브러리는 운영체제의 도움을 받아, API 함수를 통해 응용프로그램에게 파일의 끝을 알림.
    - 운영체제의 파일 시스템은 각 파일의 크기 정보를 가지고 있기 때문에, 파일 읽기가 진행되는 동안 파일 포인터가 파일의 끝에 도달하는지 확인 가능
    - 파일 포인터가 파일의 마지막 데이터를 넘어 접근하게 되면 파일의 끝에 도달하였음을 기억, 입출력 라이브러리가 요청할 때 사실 제공

##  12.8. 임의 접근
### 12.8.1. 순차 접근과 임의 접근
    - 순차 접근 : 파일의 처음부터 끝까지 순차적으로 읽거나 순차적으로 파일에 기록하는 접근 방식, get(), put(), read(), write() 등이 이에 포함됨.
    - 임의 접근 : 파일 내에 임의의 위치로 옮겨 다니면서 읽거나 쓰는 방식
    - 디폴트는 순차 접근 방식
### 12.8.2. 파일 포인터
    - 파일 : 연속된 바이트의 집합
    - 파일 포인터 : C++ 파일 입출력 스트림에 저장된 파일 내의 읽고 쓸 바이트의 위치를 가리키는 특별한 마크(mark)
    - 파일 포인터의 종류
        1. get pointer : 파일 내의 읽기 지점을 가리키는 파일 포인터
        2. put pointer : 파일 내의 쓰기 지점을 가리키는 파일 포인터
    - ifstream 이나 ios::in 즉, 읽기모드로 열린 fstream -> get pointer 만을 가진다.
    - get(), read(), getline(), >> 등의 읽기 연산은 get pointer가 가리키는 지점에서 읽고, 읽은 바이트 수만큼 get pointer 전진
    - ofstream이나 ios::out 즉, 쓰기모드로 열린 fstream -> put pointer 만을 가진다.
    - put(), write(), << 등의 쓰기 연산은 put pointer가 가리키는 위치에 데이터를 쓰고 쓴 바이트 수만큼 put pointer를 전진시킨다.
### 12.8.3. 파일 모드와 파일 포인터
    - 파일 포인터의 위치 : 파일 모드에 따라 다르게 설정
        -> 읽기 모드(ios::in)로 파일 열기 : get pointer는 파일의 맨 처음 위치 가리키기
        -> 쓰기 모드(ios::out)로 파일 열기 : put pointer를 파일의 맨 처음 위치 가리키기
        -> ios::ate 모드로 파일 열기 : put pointer를 파일의 맨 끝, 즉 EOF 위치 가리키기 여기서부터 쓰기 시작
        -> ios::app 모드로 파일 열기 : put pointer는 파일의 처음 위치를 가리키지만, 파일 쓰기를 하면 자동으로 맨 끝으로 put pointer를 옮겨서 파일의 끝에 쓰기 수행
### 12.8.4. 임의 접근 방법
    - 파일 포인터의 위치를 임의의 위치로 이동시키는게 핵심
    - 파일 포인터는 읽기나 쓰기 이후 항상 전진 but, 임의의 위치로 이동 가능
        -> streampos : 절대적 위치 값 -> long 타입
        -> streamoff : 상대적 위치 값 -> long 타입
        -> seekbase에 사용되는 상수
            - istream& seekg(streampos pos) : 정수 값으로 주어진 절대 위치 pos로 get pointer 옮김
            - istream& seekg(streamoff offset, ios::seekdir seekbase) : seekbase를 기준으로 offset 만큼 떨어진 위치로 get pointer 옮김
            - ostream& seekp(streampos pos) : 정수 값으로 주어진 절대 위치 pos로 put pointer 옮김
            - ostream& seekp(streamoff offset, ios::seekdir seekbase) : seekbase를 기준으로 offset 만큼 떨어진 위치로 put pointer 옮김
            - streampos tellg() : 입력 스트림의 현재 get pointer 값 리턴
            - streamoff tellp() : 출력 스트림의 현재 put pointer 값 리턴
        -> seekbase로 사용되는 ios::seekdir 타입의 상수
            - ios::beg : 파일의 처음 위치를 기준으로 파일 포인터를 움직임.
            - ios::cur : 현재 파일 포인터의 위치를 기준으로 파일 포인터를 움직임.
            - ios::end : 파일의 끝(EOF)위치를 기준으로 파일 포인터를 움직임.
    - 파일 포인터는 인덱스 0부터 시작
    - seekg()와 tellg()는 입력 스트림에서만 사용
    - seekp()와 tellp()는 출력 스트림에서만 사용
    -> 옮기기는 책에서 확인
### 12.8.5. 파일 포인터를 이용하여 파일 크기 알아내기
    - C++ 표준 입출력 라이브러리에서는 파일 크기를 아는 방법을 제공하지 않음.
    - 파일 포인터를 파일의 맨 끝으로 이동시킨 뒤, 파일 포인터의 크기를 알아내면 그 값이 파일의 크기
