##  8.2 클래스 상속과 객체
### 8.2.1. 상속 선언
    - class 선언 뒤에, 콜론(:)과 기본 클래스 이름 선언
    - 기본 클래스 이름 앞에 반드시 상속 접근 지정 필요 (ex. public, private, protected)
    - 상속 횟수는 제한 없음.
    - 상속 선언
### 8.2.2. 파생클래스 객체와 멤버 호출
    - 상속 선언
        -> class ColorPrint : public Point {
            ...
        }
    - 파생 클래스 객체 생성
        -> 파생 클래스의 객체는 기본 클래스의 멤버와 파생 클래스의 멤버 모두 가진다.
    - 파생 클래스에서 기본 클래스 멤버 접근
        -> 상속을 통해 기본 클래스의 멤버를 자신의 멤버로 확장
        -> 파생 클래스의 멤버들은 private 멤버 외에 모든 멤버 접근 가능
    - 기본 클래스의 private 멤버의 상속과 접근
        -> 기본 클래스의 private 멤버도 파생 클래스에 상속
        -> 파생 클래스가 생길 때 파생 클래스의 객체 내에 생성
        -> 하지만 private 멤버의 접근은 기본 클래스의 멤버만 접근 가능
    - 클래스 외부에서 파생 클래스의 멤버 호출
        -> public 으로 선언된 기본 클래스의 멤버들은 main에서 파생 클래스의 객체를 통해 호출될 수 있음.

### 8.2 정리 => 상속 관계로 클래스 간결화

##  8.3 상속과 객체 포인터
### 8.3.1 상속과 객체 포인터 - 업 캐스팅
    - 기본 클래스의 포인터로 파생 클래스의 객체를 가리키는 것
        -> 파생 클래스 객체가 기본 클래스 멤버를 포함하기 때문
        ex. Point* pBase = pDer;(업 캐스팅)
    - 상속 관계에서 강제 타입 변환 명시 생략가능
    - 기본 클래스 포인터는 파생 클래스의 멤버 중 기본 클래스의 public 멤버까지만 접근 가능
        -> 만약 파생 클래스 멤버에 접근하려고 하면 컴파일 오류
### 8.3.2 상속과 객체 포인터 - 다운 캐스팅
    - 기본 클래스 포인터가 가리키는 객체를 파생 클래스의 포인터로 가리키는 것
    - 타입 변환 명시 필요
        -> pDer = (ColorPoint*)pBase;
    -> 다운 캐스팅의 런타임 에러(실행 오류)
    pDer은 ColorPoint의 포인터 객체지만, 다운 캐스팅을 했으므로
    setColor멤버에서 컴파일 오류가 나지 않지만 멤버 함수가 pDer의 공간에 없기 때문에 런타임 에러가 발생함.
#   정리
    - 기본 클래스의 포인터로 파생 클래스의 객체를 가리킨다 : 업 캐스팅 (기본 포인터->파생 객체)
        - 업캐스팅은 기본 클래스가 파생 클래스의 멤버를 가지고 있지 않기 때문에 컴파일 오류
    - 파생 클래스의 포인터로 부모 클래스의 객체를 가리킨다 : 다운 캐스팅 (파생 포인터->기본 객체)
        - 다운캐스팅은 파생 클래스는 기본 클래스의 멤버를 가지고 있지만, 파생클래스가 가리키는 공간에 파생 클래스의 멤버가 없으므로 런타임 오류

##  8.5. 상속과 생성자, 소멸자
### 8.5.1. 파생 클래스와 기본 클래스의 생성자 호출 및 실행 관계
    - 파생 클래스의 객체가 생성될 때 파생 클래스의 생성자와 기본 클래스의 생성자가 모두 실행됨.
        -> 생성자는 객체를 초기화할 목적으로 사용, 파생 클래스의 생성자는 파생 클래스의 멤버 초기화 및 초기작업 수행/ 기본 클래스의 생성자는 기본 클래스의 것 수행
    - 기본 클래스의 생성자 먼저 실행
    - 호출 : 파생->기본
    - 실행 : 기본->파생
    - 생성자의 호출 관계는 모두 컴파일러에 의해 이루어짐.
#   참고
    - 생성자의 호출 순서가 중요한 이유 : 파생 클래스의 생성자에서 기본 클래스의 생성자를 호출할 때 인자 값을 전달하기 때문문
### 8.5.2. 소멸자의 실행 순서
    - 파생 클래스 소멸자 먼저 실행, 기본 클래스 소멸자 나중 실행
### 8.5.3. 파생 클래스에서 기본 클래스 생성자 호출
    - 원래 파생 클래스의 생성자와 함께 실행할 기본 클래스의 생성자 지정 필요
    - 선정 안해주면 디폴트 기본 생성자 컴파일 (매개변수 없는거)
    - 명시적인 기본 클래스의 생성자 선택
        - B(int x) : A(x+3) {...} => 생성자 B : 생성자 A 뭐 대충 종류
    - 컴파일러의 기본 생성자 호출 코드 삽입
        -> 아무것도 안적으면 컴파일러가 묵시적으로 기본생성자(ex. A(),B()...) 집어 넣음.
#   boolalpha
    - 불린 값을 true, false로 출력되게 하는 조작자(manipulator)

##  8.6 상속 지정
### 8.6.1. private, public, protected
    - 3개 다 지정가능
#   private
    - 기본 클래스의 protected, public 멤버를 private로 계승
#   public
    - 기본 클래스의 모든 멤버 속성을 그대로 계승
#   protected
    - 기본 클래스의 protected, public 멤버를 protected로 계승

##  8.7 다중 상속
    - 다중 상속 : 하나의 파생 클래스가 여러 클래스를 동시에 상속받는 것
### 8.7.1. 다중 상속 선언
    - 다중 상속으로 파생 클래스 선언할 때 : 클래스 선언문에서 접근 지정과 함께 기본 클래스를 콤마(,)로 나열하면 됨.
    - ex. class MusicPhone : public MP3, public MobilePhone{...};
### 8.7.2. 다중 상속 활용
    - 파생 클래스는 다중 상속받은 기본 클래스들의 멤버 모두 호출 가능

##  8.8. 가상 상속 
### 8.8.0 가상 상속이 가지는 문제점과 해결방법
    - 문제점1 : 2개 이상의 부모 클래스를 상속받는 경우 각각의 부모 클래스에 같은 이름의 멤버가 있으면 모호해짐 -> 컴파일 오류 발생
### 8.8.1. 가상 상속
    - 가상 상속 선언
        -> virtual 키워드를 이용하여 가상 상속
        -> 파생 클래스의 객체가 생성될 때 기본 클래스의 멤버 공간을 오직 한 번만 할당하고, 이미 할당되어 있다면 그 공간을 공유하도록 지시
        -> 기본 클래스의 멤버 공간은 오직 한개
    - 가상 상속으로 다중 상속 문제 해결
        -> 모호성의 해결 : 가상 상속을 통해 할당된 공간 공유 (겹쳐서 2개 이상의 공간이 존재하지 않음.)
