#   10. 템플릿과 표준 템플릿 라이브러리리
##  10.1. 일반화와 템플릿
### 일반화와 템플릿 선언
    - 템플릿 : 함수나 클래스 코드를 찍어내듯이 생산할 수 있도록 일반화(generic) 시키는 도구
    - template function(=generic function) : template 키워드를 이용하여, 중복 함수들을 일반화시킨 함수
    - 템플릿 선언과 제네릭 타입
    1. template <class T> : 제네릭 타입 T 선언
    2. 제네릭 타입 : C++의 기본 타입이 아님, 일반 타입이라고도 불림.
    -> template <class T1, class T2, class T3> 이렇게도 가능
    3. template <class T> void myswap(T & a, T & b) 이렇게도 가능

##  템플릿으로부터의 구체화
    - 구체화 : 중복 함수들을 템플릿하는 과정의 역과정
    - 컴파일러가 함수의 호출문을 컴파일 할 때
    - 구체화를 통해 제네릭 함수로부터 구체적인 함수의 소스 코드 제작
    - 구체화된 함수 : 구체화를 통해 생성된 함수
    - 구체화 과정
    1. 컴파일러 - 함수의 호출문을 컴파일 할 때 함수를 찾음.
    2. 템플릿으로 선언된 함수 발견
    3. 구체화 (실인자 타입에 따라 제네릭 타입에 실인자 대입)
    4. 구체화된 함수의 소스 코드 컴파일
    5. 함수 호출 컴파일

##  템플릿 역할
    - 템플릿 함수는 컴파일 x, 호출 x
    -> 그저 함수의 틀
    - 템플릿의 역할 : 제네릭 함수 선언, 컴파일 시점 구체화시키기 위한 틀 제작
    - 템플릿 함수로부터 구체화된 버전의 함수가 컴파일되고 호출됨.

##  구체화 오류
    - 하나의 제네릭 타입으로 되어있는 매개변수를 포함한 함수는 그 매개변수가 같은 타입으로 호출되어야 한다.

##  템플릿의 장단점과 제네릭 프로그래밍
    - 장단점
    1. 소프트웨어의 생산성과 유연성 증가
    2. 포팅에 취약
    3. 컴파일 오류 메시지가 빈약하여 디버깅에 많은 어려움
    - 제네릭 프로그래밍
    1. 제네릭 프로그래밍 = 일반화 프로그래밍

##  제네릭과 매크로의 차이점
    - 제네릭은 C 언어에서의 매크로(#define)과 유사함.
    - but, 매크로는 복잡한 함수나 클래스를 표현하는데 한계
    - 템플릿보다 사용하기 어려움.
    - 매크로는 타입 안전성이 확보되지 않기 때문에 실행중 부작용을 초래할 가능성 높음.
    - 템플릿은 제네릭 타입에 적용되는 실제 타입을 검사하여 구체화과정을 거치기 때문에, 타입 안전성을 확보하고, 실행 중에 발생하는 오류의 가능성 차단

##  10.2 다양한 제네릭 함수 만들기
### 하나의 제네릭 타입을 가진 경우
    - 두 개의 매개 변수로부터 큰 값 구하기
    -> template <class T> T bigger(T a, T b);
    - 배열의 합 구하기
    -> template <class T> T add(T data[], int n);
    => T에 들어갈 수 있는 것은 int, double, long이 있다.
### 두 개 이상의 제네릭 타입을 가진 경우
    -> template <class T1, class T2> void mcopy(T1 src [], T2 dest [], int n);

### 중복 함수가 템플릿 함수보다 우선
    - 템플릿 함수와 이름이 동일한 함수가 중복되어 있을 때, 컴파일러는 중복된 함수를 템플릿 함수보다 우선하여 바인딩 함.
    ex.
    template <class T>
    void print(T array[], int n); 보다
    void print(char array[], int n)을 더 먼저 바인딩 함.

### 템플릿 함수에 디폴트 매개 변수 사용
    - 매개 변수의 자료형이 정해진 경우에만 사용 가능함. (ex. int, char, etc...)

##  10.3 제네릭 클래스 만들기
### 제네릭 클래스 개요
    - "제네릭 클래스"가 필요한 경우 : 템플릿을 이용하여 스택에 저장되는 데이터 타입을 일반화시킬 경우
##  제네릭 클래스 선언
    - 클래스 선언부와 구현부를 모두 template로 선언
    - 선언부 -
    template <class T>
    class MyStack{
        int tos;
        T data [100];
    public :
        MyStack();
        void push(T element);
        T pop();
    };
    - 구현부 -
    template<class T>
    void MyStack<T>::push(T element) {
        ...
    }
    template<class T> T MyStack<T>::pop() {
        ...
    }
##  제네릭 클래스의 구체화
    - 구체화 과정
    1. 제네릭 타입에 int 나 double을 적용하여 두 개의 구체화된 버전의 C++ 클래스 소스 생성
    2. 두 C++ 클래스를 컴파일하고 iStack 객체와 dStack 객체를 생성하도록 컴파일

##  함수의 매개 변수 타입이 제네릭 클래스일 때
    - 함수의 원형 선언
    1. int 타입의 객체
    void popAll(MyStack<int>s) {...}
    MyStack<int> iStack;
    popAll(iStack);
    2. int 타입의 객체의 참조
    void popAll(MyStack<int> &r) {...}
    popAll(iStack);
    3. int 타입의 객체의 포인터
    void popAll(MyStack<int> *p);
    popAll(&iStack)

##  두 개 이상의 제네릭 타입을 가진 제네릭 클래스
    - 
    template <class T1, class T2>
    class GClass {
        T1 data
        T2 data
    public :
        void set(T1 a, T2 b);
        void get(T1 & a, T2 & b);
    };
    template <class T1, class T2>
    GClass<T1, T2>::GClass(){...}

    template <class T1, class T2>
    void GClass<T1, T2>::set(T1 a, T2 b) {...}

    template <class T1, class T2>
    void GClass<T1, T2>::get(T1 & a, T2 & b) {...}

### 10.4 C++ 표준 템플릿 라이브러리(STL)와 활용
##  표준 템플릿 라이브러리(STL) 개요
    표준 템플릿 라이브러리 : 템플릿으로 작성된 많은 제네릭 클래스와 함수 라이브러리
    - 컨테이너(container) - 템플릿 클래스
    : 데이터를 저장하고 검색하기 위해 담아두는 자료 구조를 구현한 클래스
    -> list, queue, stack, map, set, vector 등
    - iterator - 컨테이너 원소에 대한 포인터
    : 반복자, 컨테이너의 원소들을 하나씩 순회 접근하기 위해 만들어진 컨테이너 원소에 대한 포인터
    - 알고리즘 - 템플릿 함수
    : 컨테이너의 원소에 대한 복사, 검색, 삭제, 정렬 등의 기능을 구현한 템플릿 함수, 통칭 알고리즘
    -> 컨테이너 클래스의 멤버 함수가 아님.
##  컨테이너 분류
    - 순차 컨테이너 : vector, dequeue, list 등연속적인 메모리 공간에 순서대로 값을 저장하고 읽는 컨테이너, 인덱스를 사용하여 컨테이너 내의 특정 위치에 있는 값을 읽거나 변경 가능
    - 컨테이너 어댑터 : 다른 컨테이너를 상속받아 기능 중 일부만 공개하여 기능을 제한하거나 변형한 컨테이너로 stack, queue 등이 있음.
    - 연관 컨테이너 : '키'로 '값'을 저장하고 '키'로 검색하여 '값'을 알아내는 컨테이너로서 set, map 등이 있음.
##  헤더파일
    - std 이름공간 : STL은 std 이름공간에 작성됨.
        -> using namespace std; 필요
    - vector 클래스, algorithm 함수 사용 등
        : include <~> 필요

#   10. 템플릿과 표준 템플릿 라이브러리(STL) 재정리
##  10.1 일반화와 템플릿
### 10.1.1. 함수 중복의 약점
    - 매개 변수의 타입이 달라지면 그에 맞는 함수의 소스코드를 새로 작성해야 함.
    - 전체 프로그램의 길이 늘어남.
    - 작업 도중 실수의 가능성 생김.
    - 함수의 알고리즘을 수정하게 되면 중복된 모든 함수들의 코드를 수정해야 하는 번거로움
### 10.1.2. 일반화와 템플릿 선언
    - 템플릿 : 함수나 클래스 코드를 찍어내듯이 생산할 수 있도록 일반화(generic)시키는 도구
    1. 중복 함수의 일반화
        - template 키워드 이용 -> 중복 함수들을 일반화시킨 특별한 함수 제작 가능
        - 템플릿 함수, 제네릭 함수
        - ex.
        template <class T>
        void myswap (T & a, T & b) {
            T tmp;
            tmp = a;
            a = b;
            b = tmp;
        }
    2. 템플릿 선언과 제네릭 타입
        -
