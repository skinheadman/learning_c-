##  9.1. 파생클래스에서 함수를 재정의
### 9.1.1. 파생클래스
    - 오버로딩 : 함수의 이름이 동일하고, 매개변수의 타입과 개수가 다를 때
    - 오버라이딩 : 기본클래스와 파생클래스가 있을 때, 이름이 같은 함수를 다시 정의하는 것
    - 다른 종류의 오버라이딩 
    - 정적 바인딩 : 기본 클래스에 대한 포인터로는 기본 클래스의 함수 호출, 파생 클래스의 포인터로는 파생 클래스에 작성된 함수 호출
#   참고
    - 범위 지정 연산자(::)를 이용한 Base 멤버 접근 
    : pDer->f(); // Derived의 멤버 f() 호출
      pDer->Base::f(); // Base의 멤버 f() 호출
##  9.2. 가상 함수와 오버라이딩
### 9.2.1. 가상 함수와 오버라이딩
    1. 오버라이딩의 개념
        : 파생 클래스에서 기본 클래스에 작성된 가상 함수를 재작성하여, 기본 클래스에 작성된 가상 함수를 무력화시키고, 객체의 주인 노릇을 하는 것
        - 가상 함수를 호출하면, 파생 클래스에 오버라이딩된 함수 항상 실행
    2. 가상 함수 선언과 오버라이딩
        2-1. virtual function : virtual 키워드가 붙어있는 함수 (virtual 키워드로 선언된 멤버 함수)
            -> 컴파일 할 때 정해지는 것이 아닌, 실제 실행(런타임) 때 진행되도록 미루는 키워드
        2-2. (함수)오버라이딩 : 파생클래스에서 기본클래스와 동일한 이름을 가지고 있는 함수를 호출할 때 사용
            -> 함수 재정의는 컴파일 시간 다형성, 오버라이딩은 실행 시간 다형성
            -> virtual로 선언 후, 파생클래스에서 f()를 선언할 수 있도록 도움.
            -> 가상함수를 사용해서 오버라이딩 하는 것
            -> 기본클래스의 함수 무시, 파생클래스의 함수 사용
#   참고
    - 변수 오버라이딩은 없음.
    - 가상 함수를 재정의 하는 오버라이딩 : 실행 시간에 동적 바인딩
    - 가상 함수 아니면 컴파일 시간에 결정된 함수 호출 : 정적 바인딩
    - 자바의 경우 뭐 이딴거 없고 걍 동적 바인딩 나옴.
### 9.2.2. 오버라이딩과 가상 함수 호출
    1. 오버라이딩 사례
        - virtual을 사용하여 파생 클래스에 가상 함수를 만들면 pBase->f() 를 때렸을 때, 동적 바인딩이 일어남.
    2. 오버리이딩의 목적
        - 파생 클래스들이 자신의 목적에 맞게 가상 함수를 재정의 하도록 하는 것
        - 기본 클래스의 가상 함수는 상속받는 파생 클래스에서 구현해야 할 일종의 함수 인터페이스 제공
        - 즉, 가상함수는 하나의 인터페이스에 대해 서로 다른 모양의 구현이라는 객체 지향 언어의 다형성을 실현하는 도구임.

### 9.1.2. 함수 재정의와 오버라이딩
    1. 함수 재정의(redefine)
    - 기본 클래스와 파생 클래스에서 동일한 이름의 함수를 호출
    - virtual 키워드를 사용하지 않으면 함수 재정의
    - Base와 Derived 클래스의 함수 둘 다 호출, but Base 클래스의 함수 먼저 호출

    2. 오버라이딩
    - 기본 클래스와 파생 클래스에서 동일한 이름의 함수를 호출
    - virtual 키워드를 사용하면 오버라이딩
    - Base와 Derived 클래스의 함수 중 Base class의 함수는 무시되고, Derived class의 함수 호출
    - 동적 바인딩이 일어남.(런타임 시 어떤 함수를 호출할지 결정)

### 9.2.3. 동적 바인딩
    1. 동적 바인딩 : 오버라이딩된 함수가 무조건 호출
        - 가상 함수 호출 코드 컴파일 시 : 컴파일러는 바인딩을 실행 시간에 결정하도록 미룸.
        - 가상 함수 호출시 : 객체 내에 오버라이딩된 가상 함수를 동적으로 찾아 호출 => 동적 바인딩
        - 즉, 오버라이딩은 파생 클래스에서 재정의한 가상 함수의 호출을 보장받는 선언
            -> 동적 바인딩은 실행 시간 바인딩, 늦은 바인딩이라고 부르기도 함.
    2. 동적 바인딩이 발생하는 구체적 경우
        - 동적 바인딩은 파생 클래스의 객체에 대해, 기본 클래스의 포인터로 가상 함수가 호출될 때 일어남.
        - 동적 바인딩이 발생하는 경우
            1. 기본 클래스 내의 멤버 함수가 가상 함수 호출
            2. 파생 클래스 내의 멤버 함수가 가상 함수 호출
            3. main()과 같은 외부 함수에서 기본 클래스의 포인터로 가상 함수 호출
            4. 다른 클래스에서 가상 함수 호출
        - 가상 함수 호출하면, 무조건 동적 바인딩을 통해 파생 클래스에 오버라이딩 됨.
    3. 바인딩 사례
        - 기본 클래스에서 자신의 멤버를 호출하더라도 그것이 가상 함수이면 동적 바인딩 발생
        - override와 final 지시어
            - override : 오버라이딩 확인 지시
            - final : 파생 클래스에서 오버라이딩을 할 수 없게 하거나, 클래스의 상속 자체를 금지할 수 있음.
                - 가상함수의 원형 뒤 final : 파생 클래스의 가상 함수 오버라이딩 금지
                - 클래스 이름 바로 뒤 final : 상속 자체를 금지
### 9.2.4. C++ 오버라이딩의 특징
    1. 오버라이딩 성공 조건과 실패 조건
        - 가상 함수의 이름과 매개 변수 타입, 개수뿐 아니라 리턴 타입도 일치해야 오버라이딩 성공
    2. 오버라이딩 시 virtual 지시어 생략 가능
        - 가상 함수의 virtual 속성 : 상속되는 성질이 있음.
            -> 파생 클래스에서 virtual 키워드 생략 가능
    3. 가상 함수의 접근 지정
        - private, public, protected 중에서 자유롭게 지정 가능
### 9.2.5. 오버라이딩과 범위 지정 연산자(::)
    1. 오버라이딩에 의해 무시되고 존재감을 상실한 기본 클래스의 가상 함수 : 범위 지정 연산자(::)를 사용하여 기본 클래스의 가상함수 호출 가능
        -> 정적 바인딩임
    2. 클래스의 멤버 함수에서도 범위 지정 연산자를 이용하여 기본 클래스의 가상 함수 호출 가능
        -> 정적 바인딩임.
        -> 실제 응용에서 많이 사용됨.
    3. 범위지정 연산자
        - 범위 규칙 : 동일한 이름의 변수나 함수가 여러 곳에 선언되어 있을 때, 가장 가까운 범위에 선언된 이름을 사용하는 규칙
        - 전역 범위에 있는 이름과 클래스나 블록에 있는 이름이 같으면 전역 범위의 것은 숨겨짐.
            -> 범위 지정자로 접근 가능 (::전역범위이름)
### 9.2.6. 가상 소멸자
    - 기본 클래스의 소멸자를 만들 때, 가상 함수로 작성할 것을 권함. => 파생 클래스의 객체가 기본 클래스에 대한 포인터로 delete되는 상황에서도 정상적인 소멸이 되도록 하기 위해서임.
    1. 소멸자를 가상 함수로 선언하지 않은 경우
        - 리턴 타입만 소멸되고 파생 타입의 생성자는 소멸되지 않는 문제가 발생할 수 있음.(혹은 반대)
    2. 소멸자를 가상 함수로 선언한 경우
        - 기본 클래스의 소멸자에 대한 호출 도중 동적바인딩에 의해 파생 클래스 소멸자에 대한 호출로 변하게 됨. => 자연스럽게 기본 클래스의 소멸자도 호출
    3. 생성자, 소멸자, 가상함수
        - 생성자는 가상 함수가 될 수 없음.
        - 가상 함수를 호출해도 동적 바인딩 일어나지 않음.
        - 소멸자는 가상 함수 될 수 있음.
        - 가상 함수로 만드는 것이 바람직함.
### 9.2.7. 오버로딩, 함수 재정의, 오버라이딩 비교
    - 오버로딩 : 매개 변수의 타입이나 개수가 다른 함수들을 여러 개 중복 작성하는 것
    - 오버라이딩 : 기본 클래스의 가상 함수를 파생 클래스에서 재작성하여 동적 바인딩을 유발시키는 것
    - 함수 재정의 : 가상 함수가 아닌 멤버 함수를 재작성하여 정적 바인딩으로 처리되는 것
    -> 표 함 보기

##  9.3. 가상 함수와 오버라이딩의 활용 사례
### 9.3.1. 가상 함수를 가진 기본 클래스의 목적
    1. 파생 클래스에서 각각에 맞는 기능을 작동하도록 유도
### 9.3.2. 가상 함수 오버라이딩 : 파생 클래스마다 다르게 구현하는 다형성
    1. 어떠한 경우에도 자신이 만든 함수가 호출되는 것을 보장받는다. => 다형성
### 9.3.3. 동적 바인딩 실행 : 파생 클래스의 가상 함수 실행
    1. 링크드 리스트를 이용한 모든 함수의 실행 가능
    2. 원하는 함수의 실행도 가능
### 9.3.4. 기본 클래스의 포인터 활용
    - 기본 클래스의 포인터는 링크드 리스트를 따라 이동하면서 파생 클래스의 객체들을 삽입할 수 있으며, 모든 파생 클래스의 멤버에 접근할 수 있다.

##  9.4. 추상 클래스
    - 기본 클래스의 가상 함수 : 파생 클래스에서 재정의하여 구현할 함수를 알려주는 인터페이스의 역할
    - 실행 목적이 아니라면 굳이 기본 클래스의 가상 함수에 코드 작성 필요 없음.
    - 순수 가상 함수 : 함수의 코드가 없고 선언만 있는 가상 함수
        -> 함수의 원형 뒤에 =0;으로 선언 / 코드를 가지지 않으므로 구현부에 구현하면 안됨.
### 9.4.1. 추상 클래스
    1. 추상 클래스 : 최소 하나의 순수 가상 함수를 가진 클래스
    2. 추상 클래스의 특징
        - 실행 코드가 없는 순수 가상 함수를 가지고 있으므로 불완전한 클래스이다.
        - 추상 클래스의 인스턴스(객체)를 생성할 수 없다.
        - 만들면 컴파일 오류임.
        - 하지만, 포인터는 괜찮음.
### 9.4.2. 추상 클래스의 목적
    1. 상속을 위한 기본 클래스로 활용하는 것이 목적
    2. 파생 클래스가 구현할 함수의 원형을 보여주는 인터페이스 역할
    3. 파생 클래스에서 구현해야 할 함수만 순수 가상 함수로 선언함.
        -> 나머지도 물론 있는데 굳이 전부 가상 함수로 할 필요는 없음.
### 9.4.3. 추상 클래스 상속
    1. 추상 클래스를 상속받는 파생 클래스는 자동으로 추상 클래스가 됨.
        -> 순수 가상 함수를 그대로 상속받기 때문
    2. 추상 클래스를 상속받는 파생 클래스도 인스턴스(객체)를 못 만듦.
### 9.4.4. 추상 클래스의 구현
    1. 파생 클래스에 추상 클래스의 순수 가상 함수의 코드를 작성하는 것
    2. 파생 클래스가 온전한 클래스가 되려면 상속받은 추상 클래스의 모든 순수 가상 함수를 오버라이딩하여 구현해야함.
### 9.4.5. 추상 클래스의 용도
    1. 응용프로그램의 설계와 구현을 분리
    2. 계층적 상호 관계를 가진 클래스들의 구조 제작에 적합
